# [M6-1b] Backend Webhook Handler RevenueCat

**Milestone:** M6 — Rilis v1  
**Estimasi Ukuran:** M  
**Area:** `backend`  

---

## Task Brief

- **Task ID / Judul:** `M6-1b` — Backend Webhook Handler RevenueCat
- **Tujuan:** Mengimplementasikan endpoint webhook RevenueCat untuk sinkronisasi mutasi langganan ke tabel subscriptions dan endpoint verifikasi entitlement pengguna.
- **Bagian Dokumen Acuan:** §6.3 (Tabel subscriptions), §8.2 (Billing), §10.3 (billing_verify_total), §13 (Monetisasi & Billing)
- **Input:** Payload webhook event RevenueCat, shared authorization secret header.
- **Output:** Module billing di `apps/api/src/modules/billing/` dengan endpoint `POST /v1/webhooks/revenuecat` dan `GET /v1/billing/entitlements`.

### Langkah Implementasi
1. Implementasikan endpoint `POST /v1/webhooks/revenuecat` (atau `/v1/webhooks/apple`, `/v1/webhooks/google` jika opsi B, §8.2, §13).
2. Verifikasi header otorisasi bersama (shared authorization secret) pada incoming request webhook untuk mencegah spoofing request (§13).
3. Ekstrak event langganan (INITIAL_PURCHASE, RENEWAL, CANCELLATION, EXPIRATION).
4. Upsert record ke tabel `subscriptions` di PostgreSQL (§6.3):
5.   `user_id`, `platform` ('apple'|'google'), `product_id`, `original_txn_id`, `status`, `expires_at`, `last_verified_at`.
6. Implementasikan endpoint `GET /v1/billing/entitlements` (§8.2, §13): kueri status langganan aktif pengguna berdasarkan token JWT.
7. Perbarui metrik Prometheus `billing_verify_total{platform, result}` (§10.3).

### Tes yang Harus Ada
- [ ] Security test: webhook menolak request tanpa shared secret header yang valid (401 Unauthorized).
- [ ] Integration test: webhook event pembelian berhasil memperbarui tabel `subscriptions`.
- [ ] Integration test: endpoint `GET /v1/billing/entitlements` mengembalikan status entitlement aktif yang sesuai.

### Observability yang Harus Ada
- [ ] Metrik `billing_verify_total{platform, result}` dicatat (§10.3).
- [ ] Log audit INFO untuk setiap mutasi status langganan (dengan user_hash, tanpa PII).

### Di Luar Cakupan (Out of Scope)
- Pemrosesan pembayaran langsung dengan kartu kredit / payment gateway eksternal.

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ Webhook WAJIB memvalidasi shared authorization header (§13).
- ⚠️ Validasi receipt dan status langganan WAJIB diverifikasi di server, JANGAN percaya klien (§12.1).
- ⚠️ DILARANG mencatat informasi kartu atau PII pembayaran ke log (§10.2).
