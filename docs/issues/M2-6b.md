## Task Brief

- **Task ID / Judul:** `M2-6b` — Enrichment Konten N5 (Contoh, Tokenisasi, Furigana & Audio)
- **Tujuan:** Melengkapi seluruh item N5 dengan contoh kalimat Tatoeba, tokenisasi Sudachi, anotasi segmen furigana, draf mnemonik, dan audio pra-render Opus.
- **Bagian Dokumen Acuan:** §3.2 (Sudachi/UniDic), §5.5 (Furigana segmentasi), §9.1 tahap 3 (Enrichment), §9.2 (Contoh item YAML sumber)
- **Input:** Silabus N5 dari M2-6a, kolam kalimat Tatoeba, generator TTS M2-4.
- **Output:** File item YAML lengkap di `content/n5/items/` dan aset audio di `content/assets/audio/n5/`.

### Langkah Implementasi
1. Padankan setiap kosakata N5 dengan minimal 1 kalimat contoh Tatoeba yang mayoritas katanya berada pada level N5 atau lebih rendah (§9.1 tahap 3).
2. Jalankan tokenisasi Sudachi/UniDic secara offline pada waktu build (bukan saat runtime, §3.2) untuk memecah teks kalimat dan kata.
3. Bentuk segmentasi furigana terstruktur `[{t: '漢字', r: 'かんじ'}]` pada teks Jepang kata dan contoh kalimat (§5.5, §9.2).
4. Tambahkan arti dwibahasa (Indonesia `id` dan Inggris `en`) untuk setiap item (§1, §9.2).
5. Sediakan draf mnemonik singkat kanji (jika draf dibuat bantuan LLM, tandai `provenance: llm_draft`, §3.2, §9.1).
6. Generate file audio neural TTS pra-render 2 suara (f1 dan m1) format Opus 32–48 kbps untuk seluruh kosakata dan kalimat contoh N5 menggunakan pipeline M2-4.

### Tes yang Harus Ada
- [ ] Unit test: validasi konsistensi furigana terhadap bacaan kana pada 100% item N5.
- [ ] Unit test: setiap item vocab memiliki minimal 1 file audio valid dan 1 kalimat contoh.
- [ ] Verifikasi format YAML sesuai contoh schema §9.2.

### Observability yang Harus Ada
- [ ] Log proses enrichment mencatat total kata diproses, rasio kecocokan furigana, dan file audio terbit.

- Konten N4/N3 (dikerjakan di M6-2).

- ⚠️ Item hasil draf LLM wajib diberi tanda `provenance: llm_draft` sebelum direview manusia (§3.2, §9.1).
