## Task Brief

- **Task ID / Judul:** `M3-4` — Pembungkus Scheduler + FSRS + golden test ≥50 skenario
- **Tujuan:** Mengimplementasikan interface domain Scheduler dengan engine FSRS-6 (21 parameter), fuzzing deterministik, dan golden test minimal 50 skenario terhadap referensi ts-fsrs.
- **Bagian Dokumen Acuan:** §2 (Penjadwalan FSRS-6 & konfigurasi), §5.4 (SRS engine di klien), §16.3 (Determinisme FSRS), §16.4
- **Input:** Vektor uji golden dari implementasi referensi `ts-fsrs`.
- **Output:** Interface `Scheduler` dan implementasi `FsrsScheduler` di `apps/mobile/lib/domain/srs/` beserta test suite.

### Langkah Implementasi
1. Definisikan interface: `abstract class Scheduler { ReviewResult review(CardState card, Rating rating, DateTime now); }` (§5.4).
2. Implementasikan scheduler menggunakan package Dart `fsrs` resmi dari open-spaced-repetition (WAJIB FSRS-6 dengan 21 parameter) (§2, §5.4). (Catatan: jika paket tidak kompatibel, gunakan Opsi B membungkus `fsrs-rs` Rust via flutter_rust_bridge dan catat di decision log, §5.4).
3. Terapkan konfigurasi wajib §2:
4.   - `desired_retention` default 0.90 (pilihan: 0.85 Santai, 0.90 Standar, 0.95 Ketat).
5.   - `maximum_interval` = 365 hari.
6.   - `learning_steps` = [1m, 10m], `relearning_steps` = [10m].
7.   - Fuzzing aktif dengan SEED DETERMINISTIK dari hash(`card_id`, `reps`) agar hasil replay selalu deterministik (§2, §16.3). DILARANG menggunakan random global!
8. Susun golden test suite komprehensif: import minimal 50 skenario rangkaian rating dari `ts-fsrs` (mencakup kartu baru, learning, review, lapse, easy, hard); bandingkan keluaran state, stability, difficulty, dan due.
9. Toleransi perbandingan: selisih stability/difficulty maksimal 1e-6, dan interval hari (scheduled_days) HARUS IDENTIK 100% (§5.4).

### Tes yang Harus Ada
- [ ] Golden test: minimal 50 skenario pengujian FSRS lulus 100% dengan toleransi 1e-6 dan interval hari identik terhadap ts-fsrs.
- [ ] Unit test: fuzzing deterministik menghasilkan interval yang persis sama pada review berulang dengan input yang identik.
- [ ] Unit test: penanganan transisi rating (Again=1, Hard=2, Good=3, Easy=4).

### Observability yang Harus Ada
- [ ] Logging DEBUG terstruktur saat kalkulasi FSRS (hanya saat unit test, bukan produksi).
