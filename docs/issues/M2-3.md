# [M2-3] Builder paket + publish + rollback manifest

**Milestone:** M2 — Content Pipeline dan Konten Awal  
**Estimasi Ukuran:** M  
**Area:** `content`  

---

## Task Brief

- **Task ID / Judul:** `M2-3` — Builder paket + publish + rollback manifest
- **Tujuan:** Mengembangkan builder CLI untuk mengemas konten menjadi arsip zip per-level, memverifikasi batas ukuran anggaran, mengunggah ke object storage, dan memperbarui manifest secara atomik.
- **Bagian Dokumen Acuan:** §4.2 (Storage & CDN), §6.3 (content_packs), §9.1 tahap 6 & 7 (Build & Publish), §9.3 (Anggaran ukuran dan distribusi)
- **Input:** File konten tervalidasi di `content/`, aset audio/strokes, koneksi S3/MinIO dan PostgreSQL.
- **Output:** CLI command `nihon-content build`, `nihon-content publish`, dan `nihon-content rollback`.

### Langkah Implementasi
1. Implementasikan `nihon-content build`: mengemas konten menjadi zip per level dan per jenis `pack-{level}-{kind}-v{n}.zip` (`core`, `audio`, `strokes`, `passages`, `tests`).
2. Struktur isi zip: `items.jsonl`, `lessons.json`, `manifest.json`, file audio Opus/AAC, dan file SVG KanjiVG.
3. Hitung checksum SHA-256 dan ukuran bytes dari setiap paket zip yang dihasilkan.
4. Verifikasi kepatuhan anggaran ukuran ketat sesuai §9.3:
5.   - `core` < 3 MB
6.   - `audio` < 60 MB
7.   - `strokes` < 5 MB
8.   - `passages` < 40 MB
9.   - `tests` < 30 MB
10. Implementasikan `nihon-content publish`: unggah file zip ke S3/MinIO bucket, lakukan upsert record ke tabel `content_packs`, dan perbarui manifest di server secara atomik (satu transaksi penulisan).
11. Implementasikan `nihon-content rollback`: mekanisme mengembalikan versi manifest ke versi sebelumnya secara instan jika ditemukan isu kritis pasca publikasi (§9.1 tahap 7).

### Tes yang Harus Ada
- [ ] Unit test: build paket menghasilkan struktur zip valid dan checksum SHA-256 yang akurat.
- [ ] Unit test: builder melempar error jika ukuran paket melebihi batas anggaran §9.3.
- [ ] Integration test: publish berhasil mengunggah file ke MinIO dan mencatat record di tabel `content_packs`.
- [ ] Integration test: verifikasi prosedur rollback mengembalikan versi aktif manifest ke versi n-1.

### Observability yang Harus Ada
- [ ] Log proses build dan publish mencatat nama paket, versi, ukuran bytes, SHA-256, dan URL tujuan storage.
- [ ] Metrik waktu build dan total payload ukuran paket.
