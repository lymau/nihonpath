# [M8-6] Partner Percakapan Berbasis LLM dengan Guardrail & Batasan Biaya

**Milestone:** M8 — Fase 3  
**Estimasi Ukuran:** M  
**Area:** `backend`  

---

## Task Brief

- **Task ID / Judul:** `M8-6` — Partner Percakapan Berbasis LLM dengan Guardrail & Batasan Biaya
- **Tujuan:** Mengimplementasikan fitur partner percakapan interaktif berbasis LLM dengan kontrol biaya ketat, guardrail topik pembelajaran bahasa Jepang, dan evaluasi kepatuhan privasi tersendiri.
- **Bagian Dokumen Acuan:** §1 Non-goals MVP (tanpa LLM runtime di MVP), §3.2 (Aturan LLM), §15 (M8 Fase 3 LLM conversation partner)
- **Input:** API LLM cloud aman, prompt guardrail pedagogis, konfigurasi kuota percakapan.
- **Output:** Module AI conversation di backend NestJS dan layar percakapan di Flutter.

### Langkah Implementasi
1. Catatan Fase (§1, §15): Fitur ini secara tegas berada pada Fase 3 pasca-v1 setelah validasi produk inti.
2. Rancang backend proxy AI percakapan dengan pembatasan biaya ketat:
3.   - Kuota batas pesan harian per pengguna premium untuk mencegah pembengkakan biaya API (§15);
4.   - Penegakan circuit breaker jika latency atau biaya LLM melewati batas (§11.3).
5. Implementasikan Guardrail Sistem:
6.   - Prompt sistem membatasi percakapan HANYA pada konteks latihan bahasa Jepang tingkat yang sesuai (N5 s/d N1);
7.   - Koreksi tata bahasa dan saran ungkapan natural yang sopan;
8.   - Filter keamanan konten dan pencegahan jailbreak.
9. Evaluasi Kepatuhan Privasi Tersendiri (§12.2, §15):
10.   - Minta persetujuan eksplisit pengguna sebelum mengaktifkan fitur percakapan LLM;
11.   - Dilarang mengirimkan data pribadi (PII), email, atau identitas pengguna ke penyedia model LLM eksternal.

### Tes yang Harus Ada
- [ ] Security & Guardrail test: prompt injeksi atau permintaan di luar topik belajar bahasa Jepang ditolak dengan sopan.
- [ ] Integration test: kuota pesan harian ditegakkan secara akurat; request melebihi kuota menerima 429 / kuota habis.
- [ ] Privacy audit: payload yang dikirim ke LLM terbukti bebas dari data PII pengguna.

### Observability yang Harus Ada
- [ ] Metrik Prometheus pemantauan jumlah token LLM terpakai, biaya per sesi, dan latency respons.
- [ ] Log audit transaksi AI tanpa mencatat isi teks bebas pengguna (§10.2).

### Di Luar Cakupan (Out of Scope)
- Penggunaan LLM untuk generasi konten kurikulum utama tanpa review manusia (dilarang keras sesuai §3.2, §9.1).

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ DILARANG LLM saat runtime pada MVP/v1; fitur ini hanya untuk Fase 3 (§1 Non-goals, §15 M8).
- ⚠️ Wajib kontrol biaya dan kuota pesan ketat (§15).
- ⚠️ DILARANG mengirimkan data identitas atau PII pengguna ke API LLM (§10.2, §12.2).
