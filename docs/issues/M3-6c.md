# [M3-6c] Controller Sesi Review & Transaksi DB Tunggal

**Milestone:** M3 — Flutter Inti (Offline)  
**Estimasi Ukuran:** M  
**Area:** `mobile`  

---

## Task Brief

- **Task ID / Judul:** `M3-6c` — Controller Sesi Review & Transaksi DB Tunggal
- **Tujuan:** Mengimplementasikan ReviewSessionController yang mengorkestrasi antrean review, menjalankan 1 transaksi SQLite atomik per review (log + user_cards + outbox), re-queue kartu learning, dan transisi <100ms.
- **Bagian Dokumen Acuan:** §1 NFR (Transisi <100ms, data loss 0), §3.6 (Mapping rating), §5.4 (Alur review), §16.3 (Satu review = satu transaksi), Lampiran C.1 (onAnswer pseudocode)
- **Input:** QueueBuilder M3-5, Scheduler FSRS M3-4, Drift DB M3-2.
- **Output:** StateNotifier / Riverpod provider `reviewSessionControllerProvider` di `apps/mobile/lib/features/review/` dan layar `/review`.

### Langkah Implementasi
1. Integrasikan layar rute `/review` menggunakan Forui `FScaffold` (§5.2.1, §5.3).
2. Ambil antrean kartu aktif dari `queue_builder`.
3. Implementasikan handler `onAnswer(card, rating, durationMs)` persis sesuai Lampiran C.1:
4.   `now = clock.now()`
5.   `result = scheduler.review(card.state, rating, now)`
6.   `db.transaction: insert review_logs(...) + update user_cards(...) + insert outbox(...)` (SATU TRANSAKSI ATOMIK SQLite!).
7. Mapping rating (§3.6): salah = Again(1); benar tetapi pakai hint / lambat = Hard(2); benar = Good(3); tombol Mudah = Easy(4).
8. Re-queue in-memory: jika kartu yang dijawab masih berstatus Learning/Relearning dan jatuh tempo kembali dalam sesi berjalan (due <= now + 20 menit), masukkan ulang kartu ke antrean in-memory (§5.4).
9. Picu sync tertunda dengan mekanisme debounce 5 detik (§5.4, Lampiran C.1).
10. Optimasi NFR (§1): pastikan transisi antar kartu selesai dalam waktu < 100 ms dengan 60 fps tanpa jank.

### Tes yang Harus Ada
- [ ] Unit test: eksekusi `onAnswer` terbukti menulis ke 3 tabel (`review_logs`, `user_cards`, `outbox`) dalam 1 transaksi atomik (simulasi rollback membatalkan ketiganya).
- [ ] Unit test: kartu learning yang belum lulus dimasukkan kembali ke antrean sesi berjalan.
- [ ] Performance test: pengukuran latensi transisi antar kartu < 100 ms.
