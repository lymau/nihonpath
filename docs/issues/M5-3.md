## Task Brief

- **Task ID / Judul:** `M5-3` — Load/soak/chaos test (§11.5)
- **Tujuan:** Mengeksekusi load test, soak test, dan chaos test menggunakan skrip k6 di lingkungan staging untuk memvalidasi kepatuhan target SLO dan keandalan sistem.
- **Bagian Dokumen Acuan:** §1 NFR (SLO ketersediaan 99,9%, latensi sync p95 < 500 ms), §11.1 (Model kapasitas), §11.5 (Skenario k6 lengkap)
- **Input:** Lingkungan staging yang menyerupai produksi, skrip pengujian beban k6.
- **Output:** Skrip pengujian di `tests/k6/` dan laporan hasil uji beban di `docs/reports/load-test-report.md`.

### Langkah Implementasi
1. Tulis dan eksekusi skrip pengujian beban k6 untuk 6 skenario wajib §11.5:
2.   1. Skenario 1 (Push Stabil): 500 req/s push sync selama 30 menit -> verifikasi SLO p95 < 500 ms, p99 < 1,5 s terpenuhi (§1 NFR, §10.7).
3.   2. Skenario 2 (Lonjakan Trafik): lonjakan beban 10x lipat (traffic spike) selama 5 menit -> verifikasi autoscaling dan load shedding (503 + Retry-After) jika diperlukan.
4.   3. Skenario 3 (Soak Test): pengujian beban stabil nonstop selama 8 jam -> verifikasi tidak ada kebocoran memori (memory leak) di Node.js, pool leak di Postgres, atau saturasi memori Redis.
5.   4. Skenario 4 (Pull Berat): simulasi pull dengan cursor jauh tertinggal dari ribuan client -> verifikasi latensi query UNION ALL tetap efisien dan tidak mengunci database.
6.   5. Skenario 5 (Push Paralel): eksekusi request push paralel untuk pengguna yang sama -> verifikasi `user_seq` tetap gapless tanpa deadlock.
7.   6. Skenario 6 (Chaos Test): simulasi failover master database PostgreSQL dan crash kontainer Redis saat beban aktif -> verifikasi degradasi anggun sesuai matriks §11.3.
8. Dokumentasikan hasil pengukuran latensi, throughput, dan error rate pada laporan resmi.

### Tes yang Harus Ada
- [ ] k6 test run: seluruh skenario 1 s/d 6 lolos dengan tingkat keberhasilan memenuhi SLO (SLO error rate < 0,1%).
- [ ] Verifikasi p95 latensi sync push < 500 ms di bawah beban 500 req/s.
- [ ] Verifikasi integritas sequence data: nol duplikasi dan nol gap pada `user_seq` pasca-tes.

### Observability yang Harus Ada
- [ ] Dashboard Grafana memantau metrik latensi, CPU, memori, dan pool DB secara real-time selama pengujian beban berlangsung.

### Di Luar Cakupan (Out of Scope)

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ Target kelulusan adalah SLO terpenuhi: ketersediaan 99,9%, push p95 < 500 ms (§10.7, §11.5).
- ⚠️ Pengujian beban WAJIB dijalankan di lingkungan staging terisolasi (§11.5, §14.2).
