## Task Brief

- **Task ID / Judul:** `M1-4` — Auth: OIDC Google/Apple, OTP email
- **Tujuan:** Mengimplementasikan endpoint autentikasi OIDC Google & Apple Sign-In, verifikasi OTP email via transactional email provider, serta endpoint tautkan akun.
- **Bagian Dokumen Acuan:** §4.2 (OIDC Google/Apple, email OTP), §6.3, §7.4 (Guest -> akun), §8.2, §8.3, §12.1 (Anti brute-force & anti-enumerasi)
- **Input:** Public keys OIDC Google/Apple, konfigurasi SES/Postmark, kontrak OpenAPI.
- **Output:** Endpoint `/v1/auth/oidc`, `/v1/auth/email/start`, `/v1/auth/email/verify`, dan `/v1/auth/link` di module auth.

### Langkah Implementasi
1. Endpoint `POST /v1/auth/oidc`: validasi id_token Google dan Apple Sign-In terhadap public keys resmi; cari atau buat user di `users` dan `auth_identities` (provider `google` / `apple`).
2. Endpoint `POST /v1/auth/email/start`: generate 6-digit OTP acak (TTL 10 menit, batas 5 percobaan), simpan HASH OTP di Redis; kirim kode via provider email transaksional (SES/Postmark).
3. Terapkan perlindungan anti-enumerasi: respons harus seragam tanpa memberitahukan apakah email sudah terdaftar (§8.3).
4. Endpoint `POST /v1/auth/email/verify`: verifikasi hash OTP dari Redis. Jika valid, buat/ambil user dan link ke `auth_identities` (provider `email`).
5. Endpoint `POST /v1/auth/link`: tautkan identitas Google/Apple/Email baru ke `user_id` guest yang sedang aktif. Jika identitas sudah dimiliki akun lain, kembalikan konflik (MVP tidak melakukan auto-merge diam-diam, §7.4).
6. Terapkan rate limiting Redis sliding window: 30 request/menit per IP untuk endpoint auth (§8.1).

### Tes yang Harus Ada
- [ ] Unit test: verifikasi mock OIDC token Google dan Apple.
- [ ] Integration test: alur email OTP start dan verify (kode valid -> sukses, kode salah > 5 kali -> diblokir, kode expired -> ditolak).
- [ ] Security test: endpoint start email tidak membocorkan status eksistensi email.
- [ ] Integration test: linking identitas ke guest berhasil; identitas ganda memicu konflik.

### Observability yang Harus Ada
- [ ] Metrik `auth_login_total{provider='google|apple|email', result='success|failure'}` (§10.3).
- [ ] Log audit INFO untuk registrasi dan login baru (email wajib di-hash/scrubbed, §10.2).

### Di Luar Cakupan (Out of Scope)

- Email template marketing (hanya email transaksional OTP).

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ OTP email WAJIB 6 digit, TTL 10 menit, maksimal 5 percobaan, disimpan sebagai HASH di Redis (§8.2, §8.3).
- ⚠️ DILARANG membocorkan keberadaan email pengguna (anti-enumerasi) (§8.3).
- ⚠️ Rate limit auth WAJIB 30 req/menit/IP (§8.1).
- ⚠️ DILARANG mencatat alamat email mentah atau kode OTP ke dalam log (§10.2).
