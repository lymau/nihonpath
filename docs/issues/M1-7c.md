# [M1-7c] Testing Modul Sync: Property Tests, Paralelisme & Keamanan IDOR

**Milestone:** M1 — Backend Inti  
**Estimasi Ukuran:** M  
**Area:** `backend`  

---

## Task Brief

- **Task ID / Judul:** `M1-7c` — Testing Modul Sync: Property Tests, Paralelisme & Keamanan IDOR
- **Tujuan:** Menyusun rangkaian pengujian komprehensif untuk modul sync: property-based tests aturan merge, pengujian beban push paralel bebas deadlock, dan verifikasi IDOR.
- **Bagian Dokumen Acuan:** §7.3 (Aturan merge), §11.5 (Chaos & concurrency test), §12.1 (Pencegahan IDOR), §14.4 (Strategi pengujian backend)
- **Input:** Implementasi endpoint push (M1-7a) dan pull (M1-7b).
- **Output:** Test suite di `apps/api/test/sync/` (property tests, concurrency tests, security IDOR tests).

### Langkah Implementasi
1. Tulis property-based tests (menggunakan `fast-check` atau setara) untuk memverifikasi kebenaran dan determinisme aturan merge (§7.3) dalam ribuan kombinasi variasi urutan kedatangan op.
2. Tulis tes konkurensi push paralel: jalankan minimal 10 request push simultan untuk `user_id` yang sama, verifikasi bahwa transaksi diserialisasi dengan aman tanpa deadlock dan urutan `user_seq` yang dihasilkan strictly monotonic dan gapless (§11.5, §14.4).
3. Tulis tes keamanan otomatis IDOR: verifikasi bahwa pengguna A tidak dapat mem-push data untuk pengguna B, dan pengguna A tidak dapat mem-pull data milik pengguna B (semua kueri sync terbukti mengunci `user_id` dari token JWT, §12.1).
4. Target cakupan baris kode (line coverage) modul `sync` di atas 90% (§14.4).

### Tes yang Harus Ada
- [ ] Property test: aturan merge memenuhi sifat idempoten dan deterministik.
- [ ] Concurrency test: 10 worker paralel menghasilkan seq gapless tanpa error deadlock.
- [ ] Security IDOR test: manipulasi user_id pada payload atau header selalu ditolak / diabaikan dan mengembalikan data pengguna token saja.

### Observability yang Harus Ada
- [ ] Laporan coverage test menunjukkan cakupan modul sync > 90%.

### Di Luar Cakupan (Out of Scope)
- Load test staging skala besar 500 req/s (dikerjakan di M5-3 menggunakan k6).

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ `user_id` SELALU diambil dari JWT; tes IDOR wajib membuktikan tidak ada celah (§12.1).
- ⚠️ Target coverage modul sync WAJIB > 90% (§14.4).
