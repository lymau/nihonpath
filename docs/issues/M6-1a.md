# [M6-1a] Integrasi SDK RevenueCat & Layar Paywall Klien

**Milestone:** M6 — Rilis v1  
**Estimasi Ukuran:** M  
**Area:** `mobile`  

---

## Task Brief

- **Task ID / Judul:** `M6-1a` — Integrasi SDK RevenueCat & Layar Paywall Klien
- **Tujuan:** Mengintegrasikan SDK purchases_flutter (RevenueCat), membangun antarmuka layar /paywall tanpa dark pattern, cache entitlement offline 7 hari, dan tombol pulihkan pembelian.
- **Bagian Dokumen Acuan:** §5.2 (purchases_flutter), §5.3 (/paywall), §11.3 (Degradasi RevenueCat), §13 (Monetisasi & Billing)
- **Input:** API keys RevenueCat untuk Android dan iOS, penawaran produk langganan in-app store.
- **Output:** Layar `/paywall` di `apps/mobile/lib/features/paywall/`, billing service di `lib/data/billing/`.

### Langkah Implementasi
1. Integrasikan SDK RevenueCat (`purchases_flutter`) di Flutter (pilihan default sesuai §13). Hubungkan identifier pengguna dengan `user_id` anonim / login.
2. Bangun antarmuka layar `/paywall` menggunakan Forui widgets (`FScaffold`, `FCard`, `FButton`) (§5.2.1):
3.   - Kebijakan Tanpa Dark Pattern (§13): tombol tutup silang (close button) harus terlihat jelas; dilarang menggunakan hitung mundur palsu atau diskon manipulatif.
4.   - Tampilkan harga resmi terlokalisasi langsung dari store (tier IDR di Indonesia, §13).
5.   - Wajib sertakan tombol 'Pulihkan Pembelian' (Restore Purchases) yang berfungsi (§13).
6. Implementasikan Caching Entitlement Sisi Klien (§11.3, §13):
7.   - Simpan status entitlement aktif di penyimpanan lokal aman.
8.   - Terapkan MASA TENGGANG (grace period) 7 HARI saat perangkat offline: pengguna tetap dapat mengakses fitur premium yang sudah diunduh selama masa tenggang ketika tidak ada koneksi ke RevenueCat/store (§11.3, §13).
9. Pancarkan event analitik: `paywall_viewed` dan `subscription_started` (§10.6).

### Tes yang Harus Ada
- [ ] Widget test: layar paywall me-render penawaran harga dan tombol tutup serta pulihkan pembelian.
- [ ] Integration test (Store Sandbox): pengujian pembelian in-app sandbox di Android dan iOS berhasil memberikan entitlement premium.
- [ ] Unit test: simulasi offline membuktikan entitlement tetap valid selama masa tenggang 7 hari dan kedaluwarsa setelah hari ke-8.

### Observability yang Harus Ada
- [ ] Event analitik `paywall_viewed` dan `subscription_started` tercatat di PostHog.
- [ ] Log INFO saat status entitlement lokal diperbarui.

### Di Luar Cakupan (Out of Scope)
- Metode pembayaran selain IAP resmi Apple dan Google Play (eksplisit non-goals MVP sesuai §1).
- Iklan in-app (eksplisit dilarang sesuai §13, aplikasi tanpa iklan).

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ DILARANG DARK PATTERN: tombol tutup harus jelas, tidak ada countdown palsu (§13).
- ⚠️ Tombol 'Pulihkan Pembelian' WAJIB ada (§13).
- ⚠️ Masa tenggang offline entitlement WAJIB 7 hari (§11.3, §13).
- ⚠️ Harga WAJIB ditampilkan dari store lokal (tier IDR) (§13).
