## Task Brief

- **Task ID / Judul:** `M6-3a` — Content Pipeline Reading Bertingkat & Listening
- **Tujuan:** Mengembangkan alat pipeline konten untuk materi bacaan bertingkat (analisis lexical coverage 95-98% & tokenisasi Sudachi) dan audio dialog listening multi-suara.
- **Bagian Dokumen Acuan:** §2 (Extensive reading 95-98% coverage), §3.7 (Reading & Listening), §9.1, §9.3 (Anggaran passages)
- **Input:** Teks bacaan dan naskah dialog listening N5–N3.
- **Output:** CLI command `nihon-content passages build`, file YAML di `content/passages/`, dan paket zip `pack-*-passages-v1.zip`.

### Langkah Implementasi
1. Implementasikan penganalisis bacaan bertingkat di `tools/content-cli/`:
2.   - Hitung metrik cakupan leksikal: pastikan persentase kata yang sudah dikenal oleh pengguna pada level tersebut berada di rentang 95–98% (§2, §3.7).
3.   - Eksekusi tokenisasi build-time menggunakan Sudachi dan hasilkan anotasi furigana serta kamus arti (gloss) per kata (§3.7).
4.   - Batasi panjang teks bacaan N5 pada rentang 50–150 karakter dan tingkatkan bertahap untuk N4 dan N3 (§3.7).
5. Implementasikan pipeline konten listening:
6.   - Format dialog dengan audio multi-suara pra-render.
7.   - Sediakan variasi kecepatan audio (0,75x dan 1,0x) (§3.7).
8.   - Sertakan pertanyaan pemahaman gaya soal JLPT 聴解 dan transkrip teks lengkap.
9. Kemas materi ke dalam paket zip `passages` dan verifikasi batas anggaran < 40 MB (§9.3).

### Tes yang Harus Ada
- [ ] Unit test: penganalisis leksikal memvalidasi cakupan kata 95–98% pada bacaan bertingkat.
- [ ] Unit test: tokenisasi build-time menghasilkan segmen furigana dan gloss yang tepat.
- [ ] Verifikasi ukuran paket zip passages mematuhi anggaran < 40 MB (§9.3).

### Observability yang Harus Ada
- [ ] Log output menampilkan persentase lexical coverage untuk setiap bacaan yang diproses.
