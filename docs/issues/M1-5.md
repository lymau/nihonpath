## Task Brief

- **Task ID / Judul:** `M1-5` — /me, /config, job penghapusan dan ekspor akun
- **Tujuan:** Mengimplementasikan endpoint profil /me, remote config /config, serta job async BullMQ untuk penghapusan permanen akun (UU PDP/GDPR) dan ekspor data.
- **Bagian Dokumen Acuan:** §6.3 (users), §8.2 (Endpoint Akun & Config), §11.3 (Circuit breaker), §12.2 (Privasi & Penghapusan akun)
- **Input:** Autentikasi JWT guard, BullMQ queue, S3 presigned URL generator.
- **Output:** Module user & config di `apps/api/src/modules/users/`, `apps/api/src/modules/config/`, serta background workers di `apps/api/src/jobs/`.

### Langkah Implementasi
1. Endpoint `GET /v1/me` dan `PATCH /v1/me`: ambil dan perbarui data pengguna (`display_name`, `locale` 'id'/'en', `timezone`, `target_level`). Ambil `user_id` strictly dari token JWT (§12.1).
2. Endpoint `GET /v1/config`: kembalikan remote configuration (feature flags, parameter remote, dan `min_app_version` untuk memicu layar paksa perbarui aplikasi, §8.1).
3. Endpoint `DELETE /v1/me`: inisiasi penghapusan akun; segera cabut seluruh refresh token dan set `deleted_at = now()`. Masukkan job async BullMQ untuk menghapus permanen seluruh data user (cascade delete tabel pengguna) dalam batas 30 hari serta trigger penghapusan data analitik via API PostHog (§12.2).
4. Endpoint `POST /v1/me/export`: inisiasi ekspor data; buat job async BullMQ untuk menghimpun data pengguna (kartu, review log, pengaturan, progres) ke format JSON, unggah ke S3, dan kembalikan tautan unduh bertanda tangan dengan TTL 24 jam (§8.2, §12.2).

### Tes yang Harus Ada
- [ ] Integration test: `PATCH /v1/me` memperbarui preferensi user dan memvalidasi enum locale.
- [ ] Integration test: `GET /v1/config` mengembalikan schema config dan versi min app.
- [ ] Integration test: `DELETE /v1/me` menonaktifkan akun, token tidak dapat dipakai lagi, dan job BullMQ berhasil mengeksekusi penghapusan cascade.
- [ ] Integration test: `POST /v1/me/export` menghasilkan file JSON data pengguna lengkap dan URL bertanda tangan berumur 24 jam.

### Observability yang Harus Ada
- [ ] Metrik BullMQ: `bullmq_queue_depth`, `bullmq_job_duration_seconds`, `bullmq_job_failed_total` (§10.3).
- [ ] Log audit INFO saat akun diminta dihapus atau diekspor.
