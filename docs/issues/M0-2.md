## Task Brief

- **Task ID / Judul:** `M0-2` — openapi.yaml v0 (auth, config, manifest, sync) + JSON Schema konten + generator klien Dart/TS
- **Tujuan:** Menyusun kontrak API openapi.yaml v0, JSON Schema untuk konten, serta generator otomatis klien Dart dan tipe TypeScript (Contract-First).
- **Bagian Dokumen Acuan:** §0 Aturan 2 (Contract-first), §8.1, §8.2, §9.1 tahap 5, §14.1, §14.3
- **Input:** Spesifikasi endpoint §8.2, tipe error §8.1, dan struktur data konten §9.2.
- **Output:** `packages/contracts/openapi.yaml`, file schema di `packages/contracts/json-schema/`, script generator, klien Dart ter-generate di `apps/mobile/lib/data/api/`, dan tipe TypeScript di `apps/api/src/`.

### Langkah Implementasi
1. Definisikan kontrak `packages/contracts/openapi.yaml` v0 untuk endpoint dasar: `/auth/guest`, `/config`, `/content/manifest`, `/sync/push`, `/sync/pull` dengan format error RFC 9457.
2. Definisikan JSON Schema untuk item konten (`vocab`, `kanji`, `grammar`, `kana`) di `packages/contracts/json-schema/`.
3. Konfigurasi tooling code generation: `openapi-generator-cli` dengan target `dart-dio` untuk Flutter, dan `openapi-typescript` untuk backend NestJS.
4. Buat npm/pnpm script `generate:contracts` untuk menjalankan generasi kode secara deterministik.
5. Tambahkan langkah verifikasi di CI (`.github/workflows/ci.yml`) menggunakan `oasdiff` dan git diff check untuk memastikan klien hasil generate tidak basi / out-of-sync.

### Tes yang Harus Ada
- [ ] Unit test: eksekusi script generasi kode menghasilkan klien Dart dan tipe TypeScript yang valid tanpa error kompilasi.
- [ ] CI test: verifikasi CI gagal jika ada perubahan manual pada file hasil generate atau `openapi.yaml` dimodifikasi tanpa meng-generate ulang klien.

### Observability yang Harus Ada
- [ ] Logging detail pada generator script dan CI validation check.

### Di Luar Cakupan (Out of Scope)
- Implementasi endpoint handler NestJS di backend.
- Implementasi repository data Drift di Flutter.
