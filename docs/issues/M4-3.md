# [M4-3] Pemicu sync + workmanager + backoff berjitter

**Milestone:** M4 — Auth dan Sync Klien  
**Estimasi Ukuran:** M  
**Area:** `mobile`  

---

## Task Brief

- **Task ID / Judul:** `M4-3` — Pemicu sync + workmanager + backoff berjitter
- **Tujuan:** Mengintegrasikan seluruh pemicu sinkronisasi klien: selesai sesi, aplikasi foreground, jaringan pulih (connectivity_plus), dan background periodic sync 15 menit via workmanager.
- **Bagian Dokumen Acuan:** §5.2 (workmanager, connectivity_plus), §7.4 (Pemicu sync & backoff berjitter)
- **Input:** SyncClient M4-2b, package `workmanager`, package `connectivity_plus`.
- **Output:** Class `SyncTriggerCoordinator` di `apps/mobile/lib/data/sync/sync_coordinator.dart` dan background worker callback.

### Langkah Implementasi
1. Daftarkan pemicu sinkronisasi aplikasi sesuai §7.4:
2.   1. Selesai sesi: pemicu otomatis saat sesi review atau pelajaran diselesaikan.
3.   2. App Foreground: integrasikan `WidgetsBindingObserver` / `AppLifecycleListener` untuk memicu sync saat aplikasi kembali dibuka dari background.
4.   3. Jaringan pulih: dengarkan stream `connectivity_plus`; picu sync seketika saat koneksi internet pulih dari offline.
5.   4. Pasca-login: picu sync langsung setelah login atau taut akun berhasil.
6.   5. Periodik latar belakang: konfigurasikan `workmanager` untuk menjalankan sync setiap 15 menit saat perangkat idle/terhubung internet.
7. Terapkan proteksi debouncing 5 detik pada seluruh event pemicu untuk mencegah badai request (request storms) (§7.4).
8. Pastikan penanganan concurrency lock aktif sehingga tidak ada dua proses sync yang dieksekusi bersamaan.

### Tes yang Harus Ada
- [ ] Integration test: perubahan lifecycle aplikasi ke resumed memicu fungsi sync.
- [ ] Integration test: simulasi event connectivity berubah dari none ke wifi memicu sync.
- [ ] Unit test: eksekusi 5 pemicu bersamaan dalam waktu 1 detik hanya menghasilkan 1 kali pemanggilan sync karena debouncing.

### Observability yang Harus Ada
