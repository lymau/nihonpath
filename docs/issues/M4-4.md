# [M4-4] Fault injection sync (putus, 500, lambat, 429)

**Milestone:** M4 — Auth dan Sync Klien  
**Estimasi Ukuran:** M  
**Area:** `mobile`  

---

## Task Brief

- **Task ID / Judul:** `M4-4` — Fault injection sync (putus, 500, lambat, 429)
- **Tujuan:** Menguji ketahanan modul sinkronisasi klien terhadap berbagai skenario kegagalan jaringan dan server untuk memverifikasi garansi nol kehilangan data.
- **Bagian Dokumen Acuan:** §1 NFR (Nol kehilangan data review, offline-first), §5.7 (Fault injection), §7.4 (Backoff eksponensial)
- **Input:** SyncClient dan Outbox, mock HTTP server.
- **Output:** Integration test suite di `apps/mobile/integration_test/sync_fault_test.dart`.

### Langkah Implementasi
1. Susun skenario fault injection komprehensif:
2.   1. Simulasi putus koneksi di tengah pengiriman request push (koneksi drop mendadak): verifikasi outbox tidak hilang dan berhasil dikirim ulang saat jaringan pulih.
3.   2. Simulasi server merespons HTTP 500 Internal Server Error acak: verifikasi antrean outbox bertahan dan menerapkan backoff eksponensial dengan jitter.
4.   3. Simulasi server merespons HTTP 429 Too Many Requests dengan header `Retry-After: 30`: verifikasi klien mematuhi penundaan retry.
5.   4. Simulasi respon server sangat lambat (timeout 15 detik, §11.3): verifikasi klien membatalkan request tepat waktu tanpa freeze UI.
6.   5. Simulasi mode pesawat: pengguna melakukan 50 review saat offline penuh, lalu beralih ke online -> verifikasi seluruh 50 review log terkirim ke server secara utuh tanpa ada satu pun data yang hilang (§1 NFR).

### Tes yang Harus Ada
- [ ] Integration test: skenario putus koneksi lulus tanpa data outbox hilang.
- [ ] Integration test: penanganan respon 429 dan 500 lulus dengan retry backoff yang benar.
- [ ] Integration test: skenario offline pesawat -> online sinkronisasi membuktikan nol kehilangan data.

### Observability yang Harus Ada
- [ ] Log Sentry dan metrik failure reporting diverifikasi aktif saat error terjadi.

### Di Luar Cakupan (Out of Scope)
