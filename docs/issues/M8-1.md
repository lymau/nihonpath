# [M8-1] Optimizer Server FSRS untuk Personalisasi Parameter

**Milestone:** M8 — Fase 3  
**Estimasi Ukuran:** M  
**Area:** `backend`  

---

## Task Brief

- **Task ID / Judul:** `M8-1` — Optimizer Server FSRS untuk Personalisasi Parameter
- **Tujuan:** Mengimplementasikan job batch di backend untuk mengoptimasi 21 parameter FSRS per pengguna berdasarkan minimal 1.000 review log dan menyinkronkan parameter hasil optimasi ke user_settings.
- **Bagian Dokumen Acuan:** §5.4 (Personalisasi optimizer server), §6.3 (user_settings), §15 (M8 Fase 3)
- **Input:** Partisi `review_logs` historis pengguna di PostgreSQL / storage Parquet, optimizer FSRS (Python / Rust bindings).
- **Output:** Job BullMQ di `apps/api/src/jobs/fsrs_optimizer.job.ts` dan pembaruan field `user_settings.fsrs_params`.

### Langkah Implementasi
1. Buat service batch job optimizer FSRS di backend NestJS/Worker.
2. Seleksi pengguna yang memiliki minimal 1.000 riwayat entri `review_logs` valid (§15, M8).
3. Eksekusi algoritma optimasi FSRS (menjalankan optimasi 21 parameter FSRS berbasis loss function log loss / RMSE pada memori retensi pengguna).
4. Validasi bahwa parameter hasil optimasi berada dalam batas konvergen yang wajar.
5. Perbarui field `fsrs_params` pada tabel `user_settings` pengguna dengan menaikkan field `version` dan `user_seq` (§6.3, §7.3).
6. Parameter personalisasi otomatis terkirim ke klien mobile saat sesi pull berikutnya dan diterapkan oleh Scheduler lokal klien.

### Tes yang Harus Ada
- [ ] Unit test: optimizer menolak menjalankan optimasi jika review log < 1.000 entri.
- [ ] Integration test: eksekusi job berhasil menghitung 21 parameter FSRS baru dan memperbarui `user_settings`.
- [ ] Unit test: verifikasi parameter hasil optimasi diserialisasi dengan benar dalam format JSONB.

### Observability yang Harus Ada
- [ ] Metrik BullMQ durasi eksekusi optimizer job.
- [ ] Log INFO mencatat pengguna yang menerima parameter terpersonalisasi beserta nilai loss.

### Di Luar Cakupan (Out of Scope)
- Optimasi parameter lokal on-device (beban komputasi terlalu berat untuk perangkat mobile, wajib di server sesuai §5.4, §15).

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ Minimal 1.000 review log per pengguna sebelum optimasi diizinkan berjalan (§15).
- ⚠️ Pembaruan user_settings wajib menaikkan seq dan version sesuai protokol sync (§6.3, §7.3).
