## Task Brief

- **Task ID / Judul:** `M1-3` — Auth: guest, refresh rotation + reuse detection, JWKS
- **Tujuan:** Mengimplementasikan endpoint autentikasi guest, rotasi refresh token dengan deteksi reuse pencurian token, endpoint logout, serta publikasi JWKS.
- **Bagian Dokumen Acuan:** §4.2 (Auth tanpa lock-in), §6.3 (users, auth_identities, devices, refresh_tokens), §8.2, §8.3 (Autentikasi), §12.1 (Pencegahan token theft)
- **Input:** Kontrak OpenAPI endpoint auth, skema tabel DB M1-2.
- **Output:** Module auth di `apps/api/src/modules/auth/`, controller, service, dan endpoint `/v1/auth/guest`, `/v1/auth/refresh`, `/v1/auth/logout`, `/.well-known/jwks.json`.

### Langkah Implementasi
1. Implementasikan pembuatan JWT access token berumur 15 menit menggunakan penandatanganan ES256/EdDSA dengan header `kid` pendukung rotasi key (§8.3).
2. Sediakan endpoint publik `/.well-known/jwks.json` yang mengekspos public keys (§8.3).
3. Endpoint `POST /v1/auth/guest`: buat entri di tabel `users` dengan `is_guest = true`, catat `devices`, buat `family_id` dan hash SHA-256 refresh token (256-bit entropy, TTL 30 hari), kembalikan JWT dan refresh token.
4. Endpoint `POST /v1/auth/refresh`: verifikasi hash refresh token di database. Jalankan rotasi wajib: terbitkan refresh token baru dan perbarui `replaced_by`.
5. Deteksi Reuse Token: jika token yang sudah digunakan / dicabut dipanggil kembali, deteksi sebagai pencurian token -> segera cabut SELURUH refresh token dalam `family_id` yang sama, catat audit log, dan increment metrik `auth_refresh_reuse_detected_total` (§8.3, §10.3, §12.1).
6. Endpoint `POST /v1/auth/logout`: cabut seluruh family token perangkat peminta.

### Tes yang Harus Ada
- [ ] Unit test: pembuatan JWT dengan klaim yang benar dan verifikasi JWKS publik.
- [ ] Integration test: alur `POST /v1/auth/guest` berhasil membuat akun guest dan mengembalikan pasangan token.
- [ ] Integration test: alur refresh token menghasilkan token baru dan membatalkan token lama.
- [ ] Security test: simulasi pemanggilan ulang token lama (reuse) membatalkan seluruh token dalam satu `family_id` dan menolak request berikutnya.

### Observability yang Harus Ada
- [ ] Metrik `auth_login_total{provider='guest', result='success|failure'}` (§10.3).
- [ ] Metrik `auth_refresh_reuse_detected_total` saat deteksi pencurian token (§10.3).
- [ ] Log audit INFO untuk kejadian pembuatan akun dan deteksi reuse.

### Di Luar Cakupan (Out of Scope)
- Login OIDC Google/Apple dan OTP Email (dikerjakan di M1-4).
- Penyimpanan token di klien mobile Flutter (dikerjakan di M4-1).

### Aturan Teknis Ketat & Larangan (§0, §4.3, §10, §12, §16)
- ⚠️ Access token JWT WAJIB berumur 15 menit, ditandatangani ES256 atau EdDSA (§8.3).
- ⚠️ Refresh token WAJIB 256-bit acak, disimpan sebagai HASH SHA-256 (jangan simpan token mentah) (§8.3).
- ⚠️ Deteksi pemakaian ulang refresh token WAJIB mencabut seluruh `family_id` (§8.3, §12.1).
- ⚠️ DILARANG mencatat token mentah ke dalam log (§10.2).
