## Task Brief

- **Task ID / Judul:** `M4-2c` — Client Merge Engine
- **Tujuan:** Mengimplementasikan mesin penggabungan data (merge engine) sisi klien sesuai tabel aturan resolusi konflik §7.3 dalam transaksi lokal atomik.
- **Bagian Dokumen Acuan:** §6.2 (Skema lokal), §7.3 (Aturan merge tabel lengkap), §7.4
- **Input:** Payload perubahan dari respons `GET /v1/sync/pull` M4-2b, Drift DB.
- **Output:** Class `SyncMergeEngine` di `apps/mobile/lib/data/sync/merge_engine.dart`.

### Langkah Implementasi
1. Implementasikan merge handler dalam satu transaksi lokal atomik per batch perubahan pull:
2. 1. Entitas `review_log` (§7.3): Union murni. Tidak pernah ditimpa! Jika ID log review sudah ada di SQLite lokal, abaikan (duplicate).
3. 2. Entitas `card_state` (§7.3): Last-Write-Wins (LWW) dengan aturan tie-breaker ketat:
4.    - Bandingkan dengan record lokal yang memiliki `card_id` sama.
5.    - Snapshot dengan `last_review_at` lebih besar menang;
6.    - Jika `last_review_at` sama, record dengan `reps` lebih besar menang;
7.    - Jika masih sama, record dengan `updated_at` lebih besar menang.
8.    - Terapkan snapshot pemenang ke `user_cards` (seluruh log review tetap utuh tanpa diubah).
9. 3. Entitas `settings` (§7.3): LWW berdasarkan `updated_at` yang lebih besar; field `version` meningkat.
10. 4. Entitas `lesson_progress` (§7.3): Status bersifat maju-saja (`not_started` < `in_progress` < `completed`); nilai `best_score` = nilai maksimum antara lokal dan remote.
11. 5. Entitas `test_attempt` (§7.3): Union berdasarkan ID percobaan.

### Tes yang Harus Ada
- [ ] Unit test: review_log lokal tidak pernah ditimpa oleh data pull.
- [ ] Unit test: card_state LWW menguji seluruh kondisi tie-breaker (last_review_at, reps, updated_at).
- [ ] Unit test: status lesson_progress tidak pernah mundur (completed tidak bisa kembali ke in_progress).
- [ ] Unit test: best_score pada lesson_progress mengambil nilai tertinggi.
