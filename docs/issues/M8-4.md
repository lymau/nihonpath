# [M8-4] Update Paket Konten Delta

**Milestone:** M8 — Fase 3  
**Estimasi Ukuran:** M  
**Area:** `content`  

---

## Task Brief

- **Task ID / Judul:** `M8-4` — Update Paket Konten Delta
- **Tujuan:** Mengembangkan mekanisme pembuatan dan distribusi pembaruan paket konten berbasis delta (diff) guna meminimalkan konsumsi kuota pengguna.
- **Bagian Dokumen Acuan:** §9.3 (Distribusi paket & update delta fase 2/3), §15 (M8 Fase 3)
- **Input:** Versi paket konten lama `v{n}` dan versi baru `v{n+1}`.
- **Output:** CLI command `nihon-content delta build`, format paket `pack-{level}-{kind}-v{n}-to-v{n+1}.delta.zip`, dan patch installer di klien.

### Langkah Implementasi
1. Implementasikan generator paket delta di `tools/content-cli/`:
2.   - Bandingkan file `items.jsonl` dan aset antar dua versi paket berurutan;
3.   - Hasilkan file patch biner / arsip zip delta yang hanya berisi item yang ditambah atau diubah;
4.   - Hitung SHA-256 dan daftarkan ke tabel `content_packs` dengan metadata tipe delta.
5. Implementasikan Delta Applicator di klien mobile Flutter:
6.   - Klien mendeteksi ketersediaan paket delta untuk versi yang sedang terpasang;
7.   - Unduh file delta berukuran kecil, terapkan patch ke SQLite dan penyimpanan asset lokal dalam transaksi atomik;
8.   - Jika patching delta gagal, otomatis beralih (fallback) mengunduh paket penuh secara utuh (§9.3).

### Tes yang Harus Ada
- [ ] Unit test: penerapan paket delta pada database lokal menghasilkan state data yang persis identik dengan instalasi paket penuh.
- [ ] Unit test: simulasi korupsi patch delta memicu fallback otomatis ke unduhan paket penuh.

### Observability yang Harus Ada
- [ ] Metrik perbandingan penghematan bandwidth (bytes delta vs bytes full package).
