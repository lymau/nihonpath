# [M2-2] Validator konten (§9.1 tahap 5) + laporan cakupan

**Milestone:** M2 — Content Pipeline dan Konten Awal  
**Estimasi Ukuran:** M  
**Area:** `content`  

---

## Task Brief

- **Task ID / Judul:** `M2-2` — Validator konten (§9.1 tahap 5) + laporan cakupan
- **Tujuan:** Membangun CLI validator konten dan integrasi CI yang memvalidasi integritas referensi, konsistensi furigana, kelengkapan audio, provenance manusia, dan laporan cakupan level.
- **Bagian Dokumen Acuan:** §3.2 (Aturan LLM & lisensi), §3.3 (Prinsip kanji-in-context), §9.1 tahap 4 & 5 (Validasi), §9.2 (Schema konten)
- **Input:** File YAML kurikulum di `content/`, JSON Schema dari M0-2.
- **Output:** CLI command `nihon-content validate`, laporan markdown cakupan level, dan CI step di `.github/workflows/ci.yml`.

### Langkah Implementasi
1. Implementasikan fungsi validasi skema JSON Schema pada setiap file YAML di folder `content/`.
2. Validasi integritas referensi: setiap `item_id` di `lessons` harus merujuk ke `content_items` yang ada.
3. Validasi kelengkapan asset: setiap item vocab WAJIB memiliki minimal 1 file audio dan minimal 1 kalimat contoh (§9.1 tahap 5).
4. Validasi konsistensi furigana: segmen furigana harus cocok dengan bacaan kana item.
5. Validasi prinsip kanji-in-context (§3.3, §9.1 tahap 5): kanji dalam sebuah lesson harus sudah diperkenalkan di kosakata unit sebelumnya atau lesson itu sendiri.
6. Validasi Larangan Keras LLM (§3.2, §9.1 tahap 4): item bertanda `provenance: llm_draft` DILARANG KERAS dipublikasikan! Item wajib bertanda `provenance: human_reviewed` dengan `reviewed_by` valid.
7. Validasi keunikan: tidak ada duplikasi `external_key`.
8. Generate laporan cakupan level: persentase target kosakata & kanji yang terpenuhi vs target kumulatif §3.1.
9. Integrasikan ke pipeline CI: CI WAJIB GAGAL dan memblokir merge PR jika ada satu pun pelanggaran validasi.

### Tes yang Harus Ada
- [ ] Unit test: validator mendeteksi dan menolak item dengan `provenance: llm_draft`.
- [ ] Unit test: validator mendeteksi pelanggaran kanji-in-context (kanji diajarkan sebelum diperkenalkan).
- [ ] Unit test: validator menolak vocab tanpa file audio atau contoh kalimat.
- [ ] Integration test: pipeline CI gagal saat dimasukkan file YAML yang tidak valid.

### Observability yang Harus Ada
- [ ] Output konsol menampilkan rincian error validasi baris-per-baris dan ringkasan persentase kelulusan.

### Di Luar Cakupan (Out of Scope)

- Pengisian konten kurikulum N5 (dikerjakan di M2-6).

- ⚠️ Vocab wajib punya ≥1 audio dan ≥1 contoh kalimat (§9.1 tahap 5).
- ⚠️ CI WAJIB memblokir merge jika validasi konten gagal (§9.1 tahap 5).
