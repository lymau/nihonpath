## Task Brief

- **Task ID / Judul:** `M4-2b` — SyncClient Loop Push & Pull
- **Tujuan:** Mengimplementasikan algoritma loop sinkronisasi Push & Pull sesuai §7.4, penanganan status accepted/duplicate/rejected, sinkronisasi clock offset, dan dead letter queue.
- **Bagian Dokumen Acuan:** §1 NFR (Latensi sync & nol data loss), §7.2 (Endpoint sync), §7.4 (Algoritma klien lengkap), §16.3 (Validasi jam perangkat salah)
- **Input:** OutboxManager M4-2a, Klien API Dio M4-1, Drift DB.
- **Output:** Class `SyncClient` di `apps/mobile/lib/data/sync/sync_client.dart`.

### Langkah Implementasi
1. Implementasikan fungsi `sync()` persis sesuai algoritma §7.4:
2.   1. Kunci eksekusi: jika proses sync sedang berjalan, segera return (cegah race condition).
3.   2. LOOP PUSH: ambil ops dari outbox (`ORDER BY created_at LIMIT 200`). Jika kosong, keluar loop push.
4.   3. Kirim request: `POST /v1/sync/push` membawa payload ops dan device_id.
5.   4. Evaluasi respon server per-op:
6.      - `accepted` atau `duplicate` -> hapus operasi dari tabel outbox (§7.4).
7.      - `rejected` (error 4xx permanen):
8.        * Jika kode `SYNC_CLOCK_INVALID` (§6.3, §16.3), JANGAN hapus outbox! Tampilkan banner ke pengguna 'Periksa jam perangkat Anda'.
9.        * Untuk rejected permanen lain: pindahkan ke tabel `dead_letter`, log error, dan increment metrik `sync_op_rejected_total` (§7.4).
10.      - Error jaringan / 5xx / 429: naikkan `attempts++`, hitung `next_attempt_at = now + min(2^attempts * 2s, 15 menit) + jitter(0..30%)`, dan hentikan loop push sementara (§7.4).
11.   5. LOOP PULL: panggil `GET /v1/sync/pull?cursor=<cursor>&limit=500` berulang kali sampai `has_more == false` (§7.4).
12.   6. Untuk setiap respons pull, delegasikan perubahan ke Merge Engine (M4-2c) dalam satu transaksi lokal, lalu perbarui `pull_cursor` di tabel `sync_state` (§7.4).
13.   7. Sinkronisasi waktu: simpan `clock_offset_ms = server_time - now()` di tabel `sync_state` (§7.4).

### Tes yang Harus Ada
- [ ] Integration test (mock server): alur push berhasil menghapus op yang accepted dan duplicate dari outbox.
- [ ] Unit test: op dengan error SYNC_CLOCK_INVALID tidak dihapus dari outbox dan memicu notifikasi peringatan.
- [ ] Unit test: penanganan error jaringan menghitung backoff eksponensial dengan jitter acak.
- [ ] Integration test: pull loop terus menarik batch sampai has_more bernilai false dan memperbarui cursor.
