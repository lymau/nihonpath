# [M3-8] Home, progres, forecast beban review

**Milestone:** M3 — Flutter Inti (Offline)  
**Estimasi Ukuran:** M  
**Area:** `mobile`  

---

## Task Brief

- **Task ID / Judul:** `M3-8` — Home, progres, forecast beban review
- **Tujuan:** Mengimplementasikan layar utama /home dengan rencana harian terurut, layar /progress dengan statistik retensi dan diagram batang ForecastBars, serta pencarian /library FTS5.
- **Bagian Dokumen Acuan:** §3.6 (Urutan Home & Rencana harian), §5.2.1 (Pemetaan Forui & ForecastBars), §5.3 (/home, /progress, /library), §5.5 (Pencarian FTS5), §5.6 (Performa kueri terindeks)
- **Input:** Data `user_cards`, `review_logs`, dan `user_settings` dari Drift DB.
- **Output:** Layar di `apps/mobile/lib/features/` (`home/`, `progress/`, `library/`) dan widget `ForecastBars`.

### Langkah Implementasi
1. Implementasikan layar `/home`: tampilkan urutan rencana harian persis sesuai §3.6: (1) Tombol Review jatuh tempo dengan counter, (2) Pelajaran baru berikutnya, (3) Latihan baca/dengar, (4) Drill khusus.
2. Tampilkan kalender streak harian menggunakan `FLineCalendar` atau `FCalendar` (mode tampilan saja, §5.2.1).
3. Optimasi kueri Home: wajib menggunakan indeks `(state, due)`; DILARANG memuat seluruh tabel kartu ke dalam memori (§5.6, §16.3).
4. Implementasikan layar `/progress`: tampilkan metrik 'True Retention' (% Good/Easy pada kartu Review), total kartu per status, dan leech count (§10.6).
5. Buat komponen kustom `ForecastBars`: diagram batang proyeksi beban review 7–30 hari ke depan menggunakan `CustomPainter` murni (DILARANG menambah library grafik baru! §5.2.1).
6. Implementasikan layar `/library`: telusuri item kosakata/kanji/grammar per level menggunakan virtual table FTS5 `fts_items` dengan input search bar Forui `FTextField` (§5.2.1, §5.5).

### Tes yang Harus Ada
- [ ] Widget test: layar Home me-render rencana harian dengan urutan prioritas yang benar.
- [ ] Unit test: kueri review Home terbukti menggunakan indeks dan hanya memuat kartu due.
- [ ] Widget test: `ForecastBars` me-render proyeksi beban review tanpa error painting.
- [ ] Integration test: pencarian kata di layar library via FTS5 mengembalikan item yang sesuai.

### Observability yang Harus Ada
- [ ] Event analitik produk: `app_open` dan `daily_goal_met` (§10.6).
- [ ] Trace performa cold start diukur via Sentry (target < 2.0s sampai Home, §1 NFR).
