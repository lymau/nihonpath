## Task Brief

- **Task ID / Judul:** `M1-1` — Kerangka NestJS: config tervalidasi, pino, OTel, /healthz /readyz, filter error RFC 9457, Clock
- **Tujuan:** Membangun kerangka backend NestJS (Fastify adapter) dengan konfigurasi tervalidasi Zod, logging Pino tanpa PII, OpenTelemetry tracing, error filter RFC 9457, health checks, dan abstraksi Clock.
- **Bagian Dokumen Acuan:** §4.2 (Pilihan teknologi), §8.1 (Aturan umum API), §10.2 (Logging), §10.4 (Tracing), §14.1 (Struktur monorepo), §0 Aturan 5
- **Input:** Spesifikasi teknis backend di `apps/api/`.
- **Output:** Aplikasi NestJS di `apps/api/` dengan Fastify, `AppModule`, `common/` modules, filter error global, health endpoints, dan provider `Clock`.

### Langkah Implementasi
1. Inisialisasi aplikasi NestJS menggunakan adapter Fastify dan TypeScript strict mode di `apps/api/`.
2. Implementasikan modul config 12-factor berbasis env var dengan validasi schema Zod saat aplikasi startup.
3. Integrasikan logger Pino JSON satu baris dengan field wajib (§10.2): `ts`, `level`, `service`, `env`, `version`, `trace_id`, `span_id`, `route`, `status`, `latency_ms`, `error_code`, `user_hash` (HMAC-SHA256 dari `user_id`).
4. Pasang filter/interceptor penyaring PII ketat: DILARANG mencatat email, token, kode OTP, isi jawaban bebas, IP mentah (hanya simpan /24 yang dipotong atau hash), atau payload sync penuh (§10.2).
5. Integrasikan OpenTelemetry SDK dengan auto-instrumentation HTTP, pg, dan ioredis serta propagasi W3C `traceparent` (§10.4).
6. Buat Exception Filter global yang memformat seluruh error ke RFC 9457 `application/problem+json` dengan field tambahan `code` dan `trace_id` (§8.1).
7. Buat endpoint operasional: `GET /healthz` (liveness) dan `GET /readyz` (readiness yang mengecek koneksi DB dan Redis) (§8.2).
8. Buat interface dan provider `Clock` untuk menyuplai waktu UTC ke seluruh logika bisnis (§0 Aturan 5, Dilarang `Date.now()` langsung).
