## Task Brief

- **Task ID / Judul:** `M1-8` — Rate limiting Redis + metrik §10.3 + dashboard awal
- **Tujuan:** Mengintegrasikan rate limiter sliding-window berbasis Redis, mengekspos metrik Prometheus sesuai spesifikasi §10.3, dan menyiapkan dashboard Grafana awal.
- **Bagian Dokumen Acuan:** §8.1 (Rate limit), §10.3 (Metrik penamaan Prometheus), §10.7 (Dashboard awal), §11.3 (Degradasi fail-open Redis)
- **Input:** Redis client ioredis, Prometheus client prom-client, NestJS interceptors.
- **Output:** Rate limiter guard di `apps/api/src/common/guards/rate-limit.guard.ts`, metrics service di `apps/api/src/common/telemetry/`, endpoint `/metrics`, dan file dashboard Grafana `infra/grafana/dashboards/`.

### Langkah Implementasi
1. Implementasikan Redis sliding-window rate limiter guard dengan ambang batas sesuai §8.1:
2.   - Endpoint auth: 30 request/menit per IP.
3.   - Sync push: 30 request/menit per user.
4.   - Endpoint lainnya: 120 request/menit per user.
5.   - Respons pelanggaran: status 429 Too Many Requests dengan header `Retry-After` (§8.1).
6.   - Matriks degradasi (§11.3): jika Redis mengalami gangguan, rate limit fail-open dengan batas lokal memori per pod agar layanan tidak lumpuh.
7. Ekspos metrik Prometheus lengkap pada endpoint internal `/metrics` sesuai tabel §10.3:
8.   `http_server_request_duration_seconds`, `sync_push_ops_total`, `sync_push_batch_size`, `sync_pull_changes_returned`, `sync_clock_invalid_total`, `review_logs_ingested_total`, `db_query_duration_seconds`, `db_pool_in_use`, `db_pool_waiting`, `bullmq_queue_depth`, `bullmq_job_duration_seconds`, `bullmq_job_failed_total`, `auth_login_total`, `auth_refresh_reuse_detected_total`, `partition_default_rows`.
9. Terapkan aturan kardinalitas ketat (§10.3): label TIDAK BOLEH berisi `user_id`, `device_id`, atau URL penuh.
10. Buat dashboard Grafana JSON awal untuk Service Overview (RED metrics) dan Sync Health.
